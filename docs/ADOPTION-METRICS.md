# Adoption metrics

How to measure whether the pack helps, without overclaiming. The log stays free of personal data.

## Contents
1. What to log per session
2. Rules for reporting
3. Session log
4. Training feedback

## 1. What to log per session

| Field | Notes |
|---|---|
| Date | |
| Skill | |
| User role | Role, not name (e.g. "development coordinator") |
| Minutes before | The user's estimate for a recent comparable task done without the skill. **Self-reported** |
| Minutes with the skill | Including checking and fixing the output |
| Edits needed | none / light / heavy |
| Problems | One line each; anything that should become a break-it case |

## 2. Rules for reporting

- Report **ranges and N** ("3 sessions, 20–45 minutes saved, self-reported"), never a single average from a handful of sessions.
- Label self-reported numbers as self-reported.
- **Never extrapolate** one session to annual savings.
- Count sessions where the skill made things slower or wrong; leave nothing out.
- Use the evidence levels from the README: piloted (L4) only once a real organization used a skill on real work, with this log filled in.
- No names, donor details or file contents in the log.
